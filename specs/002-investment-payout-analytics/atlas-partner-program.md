# Atlas Partner Program

Документ фиксирует рабочую логику партнёрской программы Atlas System для аналитики, симуляции первой вкладки и будущего API-слоя.

## 1. Главный принцип

Партнёрская программа Atlas построена как:

- линейная модель
- многоуровневая карьерная лестница
- система компрессии
- matching bonus начиная с `Master`

Ключевой смысл:

- структура считается на неограниченную глубину
- процент участия зависит от статуса
- статус зависит от личной активности, первой линии и общего объёма структуры
- система платит не “за место сверху”, а за активность и разницу в статусах

## 2. Когда начисляется партнёрский бонус

Партнёрский бонус начисляется **сразу в момент создания Smart Cycle**, а не в момент его завершения.

Это значит:

- участник структуры открывает новый Smart Cycle
- система определяет сумму цикла
- система определяет расчётную добавочную дельту
- система сразу начисляет партнёрский бонус по текущему статусу аплайна

Для treasury-модели это критично:

- партнёрская нагрузка возникает в день открытия новых циклов
- а не только в день их maturity
- поэтому обзор дня должен отслеживать `referral pressure from cycle creation`, а не только исходящие выплаты по самим циклам

## 3. Базовая экономическая единица

Партнёрский бонус в Atlas считается не от всей суммы депозита, а от **расчётной добавочной дельты** Smart Cycle.

Пример:

- цикл: `100$`
- расчётная добавочная дельта: `22.5$`
- статус `Start`: `15%`
- бонус: примерно `3.3$`

Следовательно, для аналитики нужны отдельные поля:

- `cycle_amount`
- `calculated_delta_amount`
- `partner_bonus_rate`
- `partner_bonus_amount`

## 4. Активация партнёрской программы

Чтобы открыть стартовый статус `Start`, участнику достаточно создать собственный Smart Cycle на `10$`.

После этого:

- активируется право на партнёрский доход
- стартовый процент по добавочной дельте: `15%`

## 5. Карьерная лестница

### Ступени

- `Start`
- `Builder - 1` ... `Builder - 7`
- `Master - 1` ... `Master - 7`
- `Strategist`
- `Ambassador`
- `Architect`
- `Executive`

### Логика роста

#### Builder

- зона раннего структурного роста
- процент растёт по `3%` за уровень

#### Master

- зона лидеров с крупной командой
- процент растёт по `2%`
- появляется `matching bonus`

#### Leadership tiers

- `Strategist`
- `Ambassador`
- `Architect`
- `Executive`

На этих уровнях:

- процент растёт по `2.5%`
- открывается максимальная глубина участия в партнёрской экономике
- matching доходит до `25%`

## 7. Как считать структуру

В Atlas учитываются три слоя активности:

1. личный активный Smart Cycle
2. объём `первой линии + 50% второй линии`
3. общий объём структуры на глубину

Важно:

- первая линия входит в общий объём структуры
- общий объём структуры не равен простому суммированию всех уровней

## 8. Вес глубины

Для расчёта общего объёма структуры действует weighting:

- линии `1-5` учитываются в `100%`
- линии `6-10` учитываются в `50%`
- линии `11+` учитываются в `10%`

Это нужно учитывать в аналитике при расчёте:

- `weighted_structure_volume`
- `tier_eligibility`
- `future tier jump`

## 9. Компрессия

Atlas использует компрессию, чтобы вышестоящий партнёр получал не весь процент структуры снизу, а только **разницу между своим статусом и статусом нижестоящего**.

Пример:

- ваш статус: `Builder - 1 = 18%`
- статус лично приглашённого: `Start = 15%`
- ваша компрессионная дельта: `3%`

Если нижестоящий партнёр развивается быстрее и обгоняет вас по статусу:

- его основной доход растёт самостоятельно
- вы не забираете его полный процент

Следствие для аналитики:

- `direct referral burden` нельзя считать грубым общим процентом сверху вниз
- нужно видеть распределение статусов по веткам
- нужно уметь считать `delta gap by edge`

## 10. Matching bonus

Начиная с `Master`, у партнёра появляется `matching bonus`.

Он позволяет зарабатывать с партнёрского дохода лично приглашённых лидеров, если они:

- достигли его уровня
- или обогнали его по статусу

Matching scale:

- `Master - 1`: `5%`
- `Master - 2`: `7%`
- `Master - 3`: `9%`
- `Master - 4`: `11%`
- `Master - 5`: `13%`
- `Master - 6`: `15%`
- `Master - 7`: `17%`
- `Strategist`: `19%`
- `Ambassador`: `21%`
- `Architect`: `23%`
- `Executive`: `25%`

Для аналитики matching должен считаться отдельно от direct bonus:

- `direct_partner_bonus`
- `matching_bonus`
- `total_partner_outgoing`

## 11. Что это меняет для первой вкладки

В `Обзоре` нельзя показывать одну общую метрику `Реферальная нагрузка` и считать задачу закрытой.

Нужно различать:

- `direct referral pressure`
- `matching pressure`
- `tier jump pressure`

Оператор должен видеть:

- какая часть партнёрской нагрузки пришла из новых cycle creations сегодня
- какая часть нагрузки идёт от компрессии в активной структуре
- какая часть нагрузки уже идёт из `Master+ matching`
- есть ли волна апгрейдов по статусам в ближайшие `7d`

### Branch / leader signals

- `branch_total_outgoing`

## 13. Что должно появиться в UI `Обзора`

Минимальный операторский слой:

- `Builder pressure today`
- `Master+ matching today`
- `Tier jump risk 7d`
- `Самая дорогая ветка`
- `Direct vs matching`

Эти сигналы нужны не как большая MLM-таблица, а как короткий слой над `treasury risk`.

## 15. Вывод

Партнёрская программа Atlas для аналитики — это не просто “процент с команды”.

Это отдельный финансовый слой, который:

- начинает создавать нагрузку в момент открытия новых циклов
- растёт через компрессию и статусы
- меняет поведение treasury уже в течение дня
- и особенно усиливается, когда база входит в `Master+` и включается matching

Поэтому для daily overview партнёрка должна считаться как самостоятельный treasury-pressure engine.
