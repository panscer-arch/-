# MVP Spec

## Product core

`Лайфкодинг` — это рациональная платформа, где пользователь:

- изучает правила жизни
- применяет их
- фиксирует личный опыт
- видит прогресс
- при желании делится результатами с другими

Главный цикл продукта:

`изучить -> применить -> зафиксировать -> увидеть прогресс`

## Main user flow

Базовый путь пользователя:

`Вход -> Dashboard -> Библиотека -> Страница правила -> Дневник -> Dashboard`

Этот цикл является ядром MVP. Если он работает хорошо, продукт имеет ценность даже без расширенной социальной логики.

## Screen map

- `Dashboard`
  - показывает состояние, прогресс и следующий шаг
- `Библиотека правил`
  - даёт выбор следующего материала
- `Страница правила`
  - связывает контент, смысл и применение
- `Дневник`
  - превращает правило в личный опыт
- `Лента`
  - даёт вторичный социальный слой
- `Профиль / настройки`
  - управляет личной средой пользователя

## Dashboard structure

### Main intent

Dashboard должен за 5 секунд отвечать на три вопроса:

- где я сейчас
- что у меня движется
- что мне делать дальше

### Block order

1. `Hero / status`
2. `Quick actions`
3. `Progress / focus overview`
4. `Recommended next`
5. `Recent study`
6. `Recent diary`
7. `Achievements`
8. `Notifications`
9. `Community activity`

### Rules

- hero — самый сильный блок экрана
- recommendations важнее, чем social activity
- community и notifications не должны ломать главный пользовательский путь
- dashboard — это экран продолжения пути, а не экран отчёта

## Library structure

- поиск
- категории
- фильтры
- сортировка
- рекомендованное правило
- рабочий список правил

Библиотека должна ощущаться как рабочий каталог, а не как витрина.

## Rule page structure

- заголовок и summary
- формат / длительность / сложность
- аудио / видео / текст / схема
- ключевые тезисы
- как это проявляется в жизни
- что проверить на себе
- действия:
  - `изучено`
  - `применено`
  - `добавить запись в дневник`
  - `в избранное`
- связанные правила
- discussion layer

Страница правила должна отвечать на вопрос: `как мне это понять, проверить и встроить в жизнь?`

## Diary structure

- создать запись
- формат записи
- приватность
- привязка к правилу
- теги
- режимы:
  - список
  - календарь
  - таймлайн

Дневник — один из смысловых центров продукта. Это не просто заметки, а фиксация применения правил.

## Feed structure

- фильтры
- composer
- публикация вывода или результата применения
- комментарии
- лайки
- сохранение
- жалоба

Лента — вторичный слой продукта. Она не должна превращать систему в шумную соцсеть.

## Content support

Контент MVP должен поддерживать:

- аудио
- видео
- текст
- схемы

Позже:

- вебинары
- презентации
- платное открытие контента

## Design direction

Базовая визуальная концепция: `Quiet System`

Принципы:

- спокойный, технологичный, взрослый интерфейс
- без эзотерического визуального языка
- сильная типографика
- минимум визуального шума
- спокойные поверхности и ясная иерархия

## Working method

Правильный порядок проектирования:

1. архитектурный каркас
2. screen logic
3. low-fi wireframes
4. mid-fi design
5. implementation

Дальше проект движется по одному экрану за раз, чтобы не утонуть в абстракции.
