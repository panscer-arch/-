# Content Moderation Framework

## Цель

Прежде чем усиливать social/community слой, нужно зафиксировать:

- какой контент у нас вообще считается ценным
- когда человеку естественно делиться записью
- где проходит quality bar
- как модерировать первые спорные кейсы

## 1. Creator loop

Нормальный путь публикации:

1. человек изучает правило
2. применяет его или размышляет о нем
3. фиксирует это в diary
4. только потом при желании публикует public version

Решение:

- публикация идет не “с пустого листа”, а из already-lived reflection
- лучший public post = не абстрактный совет, а личный маленький опыт

## 2. Share threshold

Пользователь должен публиковать не “потому что есть кнопка”, а когда выполнены условия:

- у него есть реальный маленький опыт
- запись не выглядит сырым шумом
- публикация не тревожит и не требует большой публичной смелости

Практический threshold:

- сначала личная запись
- потом легкий вопрос “поделиться?”
- public version может быть сокращенной и более безопасной по тону

## 3. Content policy

Полезный контент:

- личный опыт применения правила
- наблюдение о том, что сработало / не сработало
- спокойная конкретика
- короткие честные выводы

Нежелательный контент:

- self-promo
- шум ради шума
- агрессивные обобщения
- unsafe advice
- токсичность
- публичная терапия без границ контекста

## 4. Moderation rubric

Первые решения делим на 3 типа:

- `allow`
  Полезный, спокойный, личный, безопасный контент
- `review`
  Пограничный контент: сомнительные советы, слишком общий self-help, тревожный overshare
- `hide`
  spam, токсичность, unsafe advice, агрессивная self-promo, flood

## 5. Tone examples

Хороший тон:

- “Попробовал правило двух минут перед работой. Стало легче начинать, но к вечеру все равно срываюсь.”
- “Неделю делаю короткую утреннюю запись. Помогает заметить, что я завышаю план на день.”

Плохой тон:

- “Вот единственный способ стать продуктивным, все остальное бред.”
- “Подписывайтесь на мой канал, там весь настоящий лайфкодинг.”
- “Если вы не можете держать дисциплину, значит вы просто слабые.”

## Итог

26-я задача считается выполненной, если зафиксированы:

- creator loop
- share threshold
- content policy
- moderation rubric
- tone examples

Это дает рамку для развития community без скатывания в шумный self-help feed.
