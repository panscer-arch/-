# Habit & Return Loop

## Цель

Сделать так, чтобы человек:

- в первый заход не утонул в настройках
- быстро получил первую пользу
- сделал один маленький осмысленный шаг
- понял, зачем вернуться завтра

## 1. Первый 10-минутный проход

Первая сессия не должна быть длинной onboarding-анкетой.

Правильный путь:

1. выбрать или получить одно подходящее правило
2. открыть его сразу
3. сделать маленькое действие
4. зафиксировать короткую запись
5. увидеть это на dashboard

То есть первый сеанс = не “рассказ о продукте”, а первый завершенный цикл.

## 2. Первый commit

На старте человеку нужен не большой план, а очень маленький commit.

Подходит одно из трех:

- выбрать одно правило на сегодня
- нажать “начать” по одному правилу
- включить тихий reminder / план на завтра

Решение:

- первый commit = одно правило + один следующий шаг
- не просим человека обещать слишком много

## 3. Ultra-short diary

Первая запись в дневник должна быть почти без friction.

Baseline:

- one-line input
- короткий reflection prompt
- быстрый save без сложного форматирования

Решение:

- первый diary mode = короткая запись, а не длинный journaling editor
- full reflection layer можно развивать позже

## 4. Return prompts

Возврат не должен быть шумом.

Нужны не “общие напоминания”, а тихие return prompts:

- ты остановился вот здесь
- у тебя уже есть следующий шаг
- можно вернуться за 2–5 минут

Тон:

- спокойный
- личный
- без давления и guilt

## 5. Habit model

Что считаем днем практики:

- не идеальный большой прогон
- а минимальный осмысленный цикл

Минимум на день:

- открыть одно правило
- сделать один шаг
- зафиксировать короткую запись или обновить прогресс

Решение:

- daily habit не должен требовать много времени
- планка должна быть низкой, чтобы человек мог возвращаться стабильно

## Итог

25-я задача считается выполненной, если мы зафиксировали:

- как выглядит первый полезный сеанс
- что считается первым commit
- как упростить первую запись в дневник
- каким должен быть quiet return prompt
- что считаем минимальным днем практики

Это не final UX-polish, а поведенческий каркас продукта.
